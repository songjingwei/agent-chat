# 明日计划 (2026-03-29)

- 计划日期：`2026-03-29`
- 对应阶段：`Day 7 — Personality Assessment 深化`

## 核心目标
完成“测评结果解释与人格校准”从同步 heuristic 到异步可扩展流水线的升级，确保可追溯、可回滚、可观测。

## 详细任务清单

### 1. Assessment 解释任务异步化
- **目标**：将测评解释从 `AssessmentService` 内同步逻辑迁移为 Worker 任务。
- **具体任务**：
  - 新增 `assessment-interpretation` 队列任务定义与 processor。
  - 会话答题完成后只负责落状态与入队，不在请求线程内执行解释。
  - 解释任务失败时写入 `assessment_interpretations.error_code` 并保持可重试。
- **预期产出**：测评解释具备异步执行能力，不阻塞用户提交答案。

### 2. 专家解释输出协议落地
- **目标**：明确并实现 LLM 结构化输出协议。
- **具体任务**：
  - 定义 `dimension_scores/confidence/evidence/memory_writes/persona_patch/auto_apply` 的 Zod schema。
  - 在 runtime 层增加解析失败 fallback 与诊断日志。
  - 将结果写入 `assessment_interpretations.raw_output` 便于审计与排错。
- **预期产出**：解释结果可机器校验，且失败可追踪。

### 3. Persona 自动校准与版本快照
- **目标**：把解释结果安全地应用到 Persona。
- **具体任务**：
  - 基于阈值策略决定是否 `auto_apply`。
  - 应用前写入 `persona_versions` 快照，记录 `change_source=assessment_calibration`。
  - 更新 `agent_personas` 时补齐 `updated_by` 与来源引用，保证可回滚。
- **预期产出**：人格更新链路具备版本化与审计能力。

### 4. 回归测试与联调验证
- **目标**：补齐测评主链路自动化验证。
- **具体任务**：
  - API 集成测试覆盖：创建测评会话 → 提交答案 → 触发解释 → 读取结果。
  - 校验内存写入、版本快照、session 状态流转。
  - 执行 `pnpm --filter @agent/api test` 与 `pnpm --filter @agent/api typecheck`。
- **预期产出**：测评链路具备稳定回归护栏。

## 预期成果
1. Assessment 解释与人格校准形成异步 Worker 化闭环。
2. 解释输出结构可校验、失败可追踪、应用可回滚。
3. 回归测试覆盖 Day 7 核心流程。

## 风险与依赖
- **风险**：LLM 输出不稳定导致结构化解析失败，需要清晰 fallback 策略。
- **依赖**：Redis 队列可用，runtime 模型配置可用（OpenAI/Anthropic）。
- **资源**：需要有效的模型 API key 做联调。

## 验收标准
1. 测评完成后可异步生成解释结果且状态正确流转。
2. `auto_apply` 触发时必须写入 `persona_versions` 快照。
3. 出错场景可在 `assessment_interpretations` 看到错误码和原始输出。
4. API 回归与 typecheck 全通过。

## 备注
- 优先做“协议与状态机正确性”，其次做体验优化。
- 先保证失败可回溯，再追求自动化率。
