# 核心评估指标定义

## 概述

MVP 阶段定义 3 个核心指标，用于量化验证产品的 4 个核心价值中的 3 个：像本人、可控、有用。
评估方式统一采用 **LLM-as-Judge**，MVP 阶段成本最低、落地最快。

---

## 1. persona_fidelity（画像保真度）

**验证的核心价值**：像本人 — agent 生成的消息是否符合用户的性格、语言风格和偏好。

### 评估方法

将用户原始资料与 agent 生成的消息交给评估模型，从 3 个维度独立打分（1-5）：

| 维度 | 说明 | 评分锚点 |
|------|------|----------|
| 语言风格一致性 | 用词习惯、句式长度、口头禅、语气词 | 1=完全不像，3=部分相似，5=难以区分 |
| 性格特征一致性 | 外向/内向、幽默感、主动性、情绪表达 | 1=性格相反，3=大致吻合，5=高度一致 |
| 偏好/价值观一致性 | 话题偏好、态度立场、关系目标 | 1=明显矛盾，3=无冲突，5=精准反映 |

### 计算方式

```
persona_fidelity = mean(语言风格, 性格特征, 偏好价值观) / 5
```

归一化到 0-1 区间。

### 阈值

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| 不及格 | < 0.6 | agent 与用户差异明显，需优化 prompt 或记忆召回 |
| 及格 | ≥ 0.6 | MVP 最低要求 |
| 良好 | ≥ 0.8 | 目标水平 |

### 评估输入

- **参考资料**：用户上传的简历/聊天记录/社媒文本（原始语料）
- **待评样本**：agent 在测试会话中生成的 N 条消息（建议 N ≥ 10）

---

## 2. controllability（可控性）

**验证的核心价值**：可控 — 用户亲自聊天后，agent 后续行为是否向用户真实表现靠拢。

### 核心机制

用户不是给 agent 下指令，而是**亲自参与对话**。这些真实聊天记录作为新语料反哺到 agent 的画像/记忆层，使 agent 在后续自主对话中更像用户本人。

### 评估方法

在同一会话场景下，对比用户介入前后 agent 的表现变化：

1. **阶段 A（介入前）**：agent 自主对话，采集 K 轮消息。
2. **用户介入**：用户亲自聊天 M 轮，语料写入记忆层。
3. **阶段 B（介入后）**：agent 再次自主对话，采集 K 轮消息。

让评估模型对比：
- 用户亲自聊的 M 条消息（作为"标准答案"）
- 阶段 A 的 agent 消息 vs 阶段 B 的 agent 消息

从 3 个维度打分（1-5），评估 agent 与用户真实表现的**相似度变化**：

| 维度 | 说明 |
|------|------|
| 语言风格靠拢 | 介入后 agent 的用词/句式是否更接近用户本人 |
| 态度/立场靠拢 | 介入后 agent 对话题的态度是否更接近用户本人 |
| 话题偏好靠拢 | 介入后 agent 的话题选择是否更接近用户本人 |

### 计算方式

```
similarity_before = LLM_judge(用户消息, 阶段A消息)  # 0-1
similarity_after  = LLM_judge(用户消息, 阶段B消息)  # 0-1
controllability   = similarity_after - similarity_before
```

正值表示 agent 在介入后变得更像用户，值越大可控性越强。

### 阈值

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| 无效 | ≤ 0 | 介入未产生正向影响，记忆层或 prompt 机制有问题 |
| 及格 | > 0.1 | MVP 最低要求，介入后有可观察的行为变化 |
| 良好 | > 0.2 | 目标水平，变化显著且方向正确 |

### 评估输入

- **用户真实消息**：用户亲自参与的 M 轮对话（建议 M ≥ 5）
- **介入前样本**：阶段 A 的 K 轮 agent 消息（建议 K ≥ 5）
- **介入后样本**：阶段 B 的 K 轮 agent 消息（建议 K ≥ 5）

## 3. summary_usefulness（总结有用性）

**验证的核心价值**：有用 — 会话总结和推荐是否准确、完整、可操作。

### 评估方法

将完整会话记录与系统生成的总结/推荐交给评估模型，从 3 个维度独立打分（1-5）：

| 维度 | 说明 | 评分锚点 |
|------|------|----------|
| 事实准确性 | 总结内容是否与对话事实一致，无捏造 | 1=多处失实，3=基本准确，5=完全准确 |
| 覆盖度 | 关键信息（兴趣重合、分歧点、互动质量）是否遗漏 | 1=严重遗漏，3=覆盖主要信息，5=全面覆盖 |
| 可操作性 | 推荐理由是否具体、可理解、能辅助决策 | 1=空洞无用，3=有参考价值，5=直接可用 |

### 计算方式

```
summary_usefulness = mean(事实准确性, 覆盖度, 可操作性) / 5
```

归一化到 0-1 区间。

### 阈值

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| 不及格 | < 0.6 | 总结质量不可接受，需优化 prompt 或上下文压缩策略 |
| 及格 | ≥ 0.6 | MVP 最低要求 |
| 良好 | ≥ 0.8 | 目标水平 |

### 评估输入

- **完整对话记录**：会话中所有消息（含 agent 和用户介入消息）
- **待评样本**：系统生成的总结文本 + 推荐列表及理由

## 人类隐式评估

LLM-as-Judge 用于离线自动化回归，但人类判断同样重要。原则：**不让用户感觉在填问卷**，而是在自然交互中采集行为信号。

### persona_fidelity 的隐式采集

| 交互形式 | 采集信号 | 映射 |
|----------|----------|------|
| 消息气泡上的"这不像我"按钮 | 用户标记某条 agent 消息不像自己 | 负向信号，关联到具体消息，可定位哪个维度出了问题 |
| agent 自我介绍预览页的"编辑"行为 | 用户修改了 agent 自动生成的自我介绍 | 修改幅度越大，说明 fidelity 越低；diff 可用于分析偏差维度 |
| 用户主动下场聊天的频率 | 某个会话中用户频繁亲自发言 | 间接负向信号 — 用户可能觉得 agent 不够像自己所以要亲自来 |

### controllability 的隐式采集

| 交互形式 | 采集信号 | 映射 |
|----------|----------|------|
| 用户介入后是否继续放手 | 介入 M 轮后，用户退出观望 vs 继续介入 | 退出观望 = 正向信号（信任 agent 已学到）；持续介入 = 负向信号 |
| "agent 学到了吗"轻提示 | 用户退出介入时，底部浮现一条"你的 agent 正在学习你的风格"，附带一个不起眼的👍/👎 | 直接但非强制的微反馈，忽略不影响体验 |
| 同一话题重复介入次数 | 用户对同一类话题反复亲自下场 | 高重复 = agent 在该话题上学习效果差 |

### summary_usefulness 的隐式采集

| 交互形式 | 采集信号 | 映射 |
|----------|----------|------|
| 总结页停留时长和滚动深度 | 用户是否认真读了总结 | 快速划走 = 可能没价值；停留阅读 = 有参考意义 |
| 推荐对象的点击/发起会话行为 | 用户是否根据推荐去行动 | 点击 = 推荐有吸引力；发起会话 = 强正向信号 |
| "不感兴趣"手势（左滑/×） | 用户划掉某条推荐 | 负向信号，可追踪是准确性问题还是偏好问题 |

### 隐式信号汇总规则

1. **不中断用户流程**：所有采集点都嵌入已有交互，不弹窗、不强制。
2. **信号记录但不即时展示分数**：后台写入 `user_feedback_signals` 表，字段包含 `user_id`、`signal_type`、`context`（关联消息/总结 ID）、`timestamp`。
3. **定期聚合**：与 LLM-as-Judge 分数加权合并，人类信号作为校准项而非替代项。
4. **可选的周期性软提问**：每隔 N 次会话结束后，在总结页底部展示一句话提问（如"这周你的 agent 表现如何？"），提供表情选择（😊/😐/😞），用户可忽略。

## 评估体系共性设计

| 项目 | 选择 | 说明 |
|------|------|------|
| 评估方式 | LLM-as-Judge | MVP 最低成本，无需人工标注 |
| 评估模型 | 与生成模型同级或更强 | 避免弱模型评强模型的偏差 |
| 输出格式 | JSON 结构化 | 每个维度包含 `score`(1-5) 和 `reasoning`(文本) |
| 测试集规模 | 20-50 条预设场景 | Day 8 构建，覆盖不同性格/话题/介入方式 |
| 回归方式 | 每次改动跑全量测试集 | 对比基线分数，防止质量退化 |
| 基线建立 | Day 8 首次运行 | 记录初始分数作为后续对比基准 |

### 评估输出示例

```json
{
  "metric": "persona_fidelity",
  "score": 0.73,
  "dimensions": {
    "language_style": { "score": 4, "reasoning": "agent 使用了与用户相似的短句风格和语气词" },
    "personality": { "score": 3, "reasoning": "幽默感体现不足，用户原文更活泼" },
    "preference": { "score": 4, "reasoning": "话题偏好与用户资料一致" }
  },
  "test_case_id": "tc-012",
  "timestamp": "2026-04-01T10:00:00Z"
}
```
